## How it was asked

The tool is `service/examples/image_spike.rs` on the AI service's branch `spike-images`: round 1 at 0598736, round 2 at 0770713. Each request is asked as follows:
- **Instructions:** the service's, chosen for the request (`instructions_for`), plus a paragraph on images. Take sizes from what is written, never the pixels. Ask where nothing is written. Draw to the overall size where chains disagree, and say so.
- **The message:** the request's own words, then the image's pixel size, then the image, at the provider's high detail.
- **The reply schema:** the service's, plus the placement:
  - round 1: `underlay` (`at`, `width`, `rotation`);
  - round 2: two `marks`, each a pixel of the image and the drawing point it shows.
- **Correction:** an invalid document is asked once more with the reason, as the service does.

Each document is run in the engine, and what it drew is described as the corpus's judge describes it.

`judge.py` reads those descriptions:
- whether the outline's box is the size written, within 0.2%;
- how many of the written sizes the drawing has, as a span of its coordinates or a dimension's value;
- for the sketches and the PDF bracket, how far two corners of the outline land from where they are in the image, through the answer's placement, in percent of the image's width.

It also draws each answer back over its image.

## Results

| | Round 1 (`underlay`) | Round 2 (`marks`) |
| --- | --- | --- |
| Sketches: outline the size written | 4/4 | 4/4 |
| Sketches: written sizes drawn | 14/14 | 14/14 |
| Scans: outline the size written | 1/4 | 4/4 |
| Scans: written sizes drawn | 9/18 | 12/18 |
| PDF pages: written sizes drawn | 5/5 | 5/5 |
| No size written: asked instead of guessing | 2/2 | not asked again |
| Placement error, sketches | 7–11% of the image's width | 9–11% |
| Placement error, the PDF bracket | (drew the whole sheet) | 5% |

- **Sizes.** The model draws to what is written, converts feet and inches, and notices when chains do not add up to their overall size. Bugbee, the telephone exchange, and the Leopold shack each say so in the reply, and the drawing goes to the overall size. It says when a size was read from proportions: the PDF bracket's 5 mm thickness, written nowhere on the sheet, is drawn and noted as an estimate. The scans' small fractional figures are where it slips. The same scan came back right in one round and wrong in the other: the telephone exchange's 20′‑11⅛″ was read as 20′‑10⅛″ once.
- **Questions.** Both images with no size were answered with a question and nothing drawn. The reply names the sizes it needs.
- **Placement.** Neither way of placing the image is precise. Run back over its image, a drawing lands from nearly on its plan (the telephone exchange) to a tenth of the image's width away, usually too small. Two marks are no better than a placement, against §8's 2%.
- **Cost and time.** About $0.003 a request at the meter's prices, nothing served from the cache, against $0.0004 to $0.0008 for a request in words. A median 17 to 19 s.

So the model reads sizes, and places the image only roughly. ADR-0042 is amended accordingly:
- the placement is a starting point;
- the user sets it exactly with `ALIGN`, two pairs of points, which an image takes because its geometry is its frame;
- L7 judges placement loosely.
